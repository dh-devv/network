# MAC 주소와 IP 주소

MAC 주소와 IP 주소는 모두 통신 대상을 구분하는 데 사용하지만, 사용하는 계층과 범위가 다르다.

## 주소 비교

| 구분 | MAC Address | IP Address(IPv4 기준) |
|------|-------------|----------------------|
| 주소 성격 | 물리적 주소 | 논리적 주소 |
| 사용하는 계층 | 데이터 링크 계층(Layer 2) | 네트워크 계층(Layer 3) |
| 길이 | 일반적인 Ethernet MAC은 48비트, 6바이트 | 32비트, 4바이트 |
| 표기 | 16진수 두 자리씩 6개 | 0~255의 10진수 4개 |
| 예시 | `00-19-D1-F0-09-FF` | `192.168.21.1` |

IPv6 주소는 128비트이다. 여기서 설명하는 IP 주소의 길이와 표기 방식은 IPv4를 기준으로 한다.

## MAC 주소

Ethernet에서 네트워크 인터페이스를 식별하고, 같은 링크에서 프레임을 전달할 때 사용하는 주소이다.

일반적으로 제조사가 인터페이스에 주소를 할당하지만, 항상 고정되어 있는 것은 아니다. 운영체제 설정이나 Wi-Fi의 주소 무작위화 기능으로 변경될 수 있다.

하나의 장비에 유선 LAN과 무선 LAN 인터페이스가 있다면 각 인터페이스는 별도의 MAC 주소를 가질 수 있다.

## IP 주소

네트워크에서 인터페이스를 논리적으로 식별하기 위해 할당하는 주소이다. 목적지 IP 주소를 기준으로 패킷을 어느 네트워크로 전달할지 판단한다.

같은 네트워크에서 서로 다른 장비에 같은 유니캐스트 IP 주소를 중복으로 할당하면 주소 충돌이 발생할 수 있다. 하지만 서로 분리된 사설 네트워크에서는 같은 사설 IP 주소를 사용할 수 있다.

네트워크 부분과 호스트 부분의 구분은 [IPv4 주소 체계와 서브넷 마스크](../Protocols/13_ipv4_addressing.md)에서 다룬다.

## IP와 MAC을 함께 사용하는 이유

최종 목적지가 다른 네트워크에 있더라도 Ethernet 프레임은 현재 링크에서 다음 장비로 전달해야 한다.

```text
IP 주소  → 최종 목적지가 어디인지 판단
MAC 주소 → 현재 Ethernet 링크에서 다음에 받을 인터페이스 식별
```

- 같은 서브넷으로 직접 전달할 때: 목적지 장비의 MAC 주소를 사용한다.
- 다른 네트워크로 전달할 때: 일반적으로 기본 게이트웨이의 MAC 주소를 사용한다.

IPv4 over Ethernet에서는 필요한 MAC 주소를 [ARP](../Protocols/09_arp.md)로 확인한다. 모든 네트워크 구간이 Ethernet을 사용하는 것은 아니므로, 모든 링크에서 MAC 주소와 ARP를 사용하는 것은 아니다.

## 도메인 이름으로 접속할 때

```text
도메인 이름
    ↓ DNS로 목적지 IP 주소 확인
목적지 IP 주소
    ↓ 경로 확인
같은 서브넷이면 목적지, 다른 네트워크이면 게이트웨이 선택
    ↓ 필요한 경우 ARP로 다음 장비의 MAC 주소 확인
Ethernet 프레임 전송
```

예를 들어 `github.com`에 접속할 때 내 PC가 원격 서버의 MAC 주소를 직접 알아내는 것은 아니다. 다른 네트워크의 서버라면 먼저 게이트웨이로 프레임을 전달한다. DNS 결과나 ARP 정보가 캐시에 있으면 기존 정보를 사용할 수 있다.

실제 전달 순서는 [LAN과 WAN의 데이터 전달 과정](../Protocols/10_lan_wan_data_delivery.md)에서 이어서 정리한다.
