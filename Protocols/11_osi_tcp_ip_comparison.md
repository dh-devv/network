# OSI와 TCP/IP 계층별 역할 비교

## 두 모델의 차이

OSI 7계층은 통신 기능을 7단계로 나누어 설명하는 참조 모델이다. 장비와 프로토콜의 역할을 이해하거나 통신 문제를 계층별로 살펴볼 때 사용한다.

TCP/IP 모델은 인터넷에서 사용하는 프로토콜 모음을 계층별로 설명한다. 여기서는 4계층 모델을 기준으로 정리한다.

OSI는 개발자만 사용하는 모델이고 TCP/IP는 하나의 프로토콜이라는 뜻은 아니다. OSI와 TCP/IP 모델은 기능을 나누어 설명하는 체계이며, TCP/IP는 실제 프로토콜 모음을 가리키는 이름이기도 하다.

## OSI 7계층

| 계층 | 역할 | 관련 개념·예시 |
|------|------|----------------|
| 7. 응용(Application) | 응용 프로그램이 네트워크 서비스를 이용하도록 지원 | HTTP, FTP, DNS |
| 6. 표현(Presentation) | 서로 이해할 수 있는 데이터 형식으로 변환 | 인코딩, 암호화·복호화, 압축·해제 |
| 5. 세션(Session) | 통신 세션을 설정하고 유지하며 종료 | 대화 관리, 동기화 |
| 4. 전송(Transport) | 출발지와 목적지 프로세스 사이의 통신 담당 | TCP, UDP, Port |
| 3. 네트워크(Network) | 다른 네트워크까지 패킷 전달 | IP 주소, Routing, Router |
| 2. 데이터 링크(Data Link) | 같은 링크에서 프레임 전달 | MAC 주소, Ethernet Frame, Switch |
| 1. 물리(Physical) | 비트를 전기·광·무선 신호로 전송 | 케이블, 전파, 커넥터 |

아래에서 위로 읽으면 다음과 같이 정리할 수 있다.

```text
1. 물리        → 신호를 보낸다.
2. 데이터 링크 → 같은 링크에서 프레임을 전달한다.
3. 네트워크    → 다른 네트워크까지 패킷을 전달한다.
4. 전송        → 프로그램 사이의 데이터를 전달한다.
5. 세션        → 통신 세션을 관리한다.
6. 표현        → 데이터 형식을 맞춘다.
7. 응용        → 네트워크 서비스를 이용한다.
```

전송 계층의 신뢰성이나 흐름 제어는 사용하는 프로토콜에 따라 다르다. TCP는 이를 제공하지만 UDP는 같은 기능을 제공하지 않는다. 또한 OSI의 세션은 TCP 연결과 정확히 같은 개념은 아니다.

## TCP/IP 4계층과 대응 관계

| TCP/IP 계층 | 역할 | 관련 프로토콜·개념 | 대응하는 OSI 계층 |
|-------------|------|--------------------|-------------------|
| 응용(Application) | 응용 프로그램에 필요한 네트워크 통신 기능 | HTTP/HTTPS, DNS, FTP, DHCP, SMTP | 5~7계층 |
| 전송(Transport) | 프로세스 간 데이터 전달 | TCP, UDP, Port | 4계층 |
| 인터넷(Internet) | IP 주소를 기준으로 네트워크 간 패킷 전달 | IP, ICMP, Routing | 3계층 |
| 네트워크 접근(Network Access) | 실제 링크를 통해 데이터 전송 | Ethernet, Wi-Fi, MAC, Frame, 전송 매체 | 1~2계층 |

OSI의 세션·표현·응용 기능은 TCP/IP 모델에서는 응용 계층에 묶어서 설명한다. 이 대응 관계는 기능을 비교하기 위한 것이며 모든 프로토콜이 한 계층에 딱 맞게 대응하는 것은 아니다.

ARP는 IPv4 주소와 링크 계층 주소를 연결하는 역할을 한다. 이 문서에서는 링크 계층에 포함해 설명하는 RFC 1122의 구분을 따른다. 교재에 따라 인터넷 계층과 함께 다루기도 한다.

## TCP와 IP의 역할

| 구분 | TCP | IP |
|------|-----|----|
| 담당 계층 | 전송 계층 | 인터넷 계층 |
| 주된 역할 | 순서가 보장되는 신뢰성 있는 바이트 스트림 제공 | 목적지 IP를 기준으로 패킷 전달 |
| 연결 | 연결 설정 후 전송 | 연결 설정 없이 전송 |
| 주요 기능 | 순서 확인, 손실 시 재전송, 흐름·혼잡 제어 | 주소 지정, 네트워크 간 전달 |

TCP는 응용 프로그램이 보낸 바이트 스트림을 세그먼트로 나누어 보내고, 수신 측에서 순서를 맞춰 전달한다. IP 자체는 패킷의 도착이나 순서를 보장하지 않는다.

```text
TCP → 데이터를 빠짐없이 순서대로 전달하도록 관리
IP  → 목적지 주소를 기준으로 패킷 전달
```
