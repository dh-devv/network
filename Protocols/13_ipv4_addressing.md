# IPv4 주소 체계와 서브넷 마스크

## IPv4 주소

IPv4 주소는 32비트, 4바이트로 구성된다. 8비트씩 나눈 네 부분을 옥텟(Octet)이라고 하며, 각 옥텟을 0~255의 10진수로 표시한다.

```text
192.168.10.100
```

각 옥텟은 8비트이므로 다음과 같이 2진수로도 표현할 수 있다.

```text
192.168.12.1
= 11000000.10101000.00001100.00000001
```

IPv4 주소 전체의 표현 범위는 `0.0.0.0`부터 `255.255.255.255`까지이다. 다만 이 범위의 모든 주소를 일반 호스트에 할당할 수 있는 것은 아니다. 네트워크 주소, 브로드캐스트 주소, 루프백 등 특별한 용도로 쓰이는 주소가 포함되어 있다.

## Classful 주소 구분

과거에는 주소의 앞부분에 따라 Class를 나누고 기본 서브넷 마스크를 정했다.

| Class | 시작 비트 패턴 | 첫 번째 옥텟 | 기본 Subnet Mask | 전통적인 용도 |
|-------|----------------|-------------|------------------|---------------|
| A | `0` | 1~126 | 255.0.0.0(`/8`) | 대규모 네트워크 |
| B | `10` | 128~191 | 255.255.0.0(`/16`) | 중간 규모 네트워크 |
| C | `110` | 192~223 | 255.255.255.0(`/24`) | 소규모 네트워크 |
| D | `1110` | 224~239 | 해당 없음 | Multicast |
| E | `1111` | 240~255 | 해당 없음 | 예약 영역 |

Class A의 비트 패턴은 첫 옥텟 0~127에 해당하지만, `0.0.0.0/8`과 루프백용 `127.0.0.0/8`을 제외한 일반적인 학습 범위를 1~126으로 적는다. `255.255.255.255`는 제한 브로드캐스트 주소로 별도의 의미가 있다.

### 예시

- `192.168.10.100`: 첫 번째 옥텟이 192이므로 전통적인 Class C 범위
- `172.16.10.20`: 첫 번째 옥텟이 172이므로 전통적인 Class B 범위
- `10.0.0.1`: 첫 번째 옥텟이 10이므로 전통적인 Class A 범위

실제 네트워크의 경계는 Class만 보고 판단하지 않는다. CIDR(Classless Inter-Domain Routing)에서는 주소와 함께 명시한 프리픽스 길이를 사용한다.

## 사설 IP와 공인 IP

사설 IP(Private IP)는 내부 네트워크에서 사용하도록 정해 둔 주소이다. 공인 IP(Public IP)는 전역적으로 할당되어 인터넷에서 라우팅에 사용할 수 있는 주소이다.

### 사설 IPv4 범위

| CIDR | 주소 범위 |
|------|-----------|
| `10.0.0.0/8` | `10.0.0.0` ~ `10.255.255.255` |
| `172.16.0.0/12` | `172.16.0.0` ~ `172.31.255.255` |
| `192.168.0.0/16` | `192.168.0.0` ~ `192.168.255.255` |

Class와 사설·공인은 서로 다른 구분 기준이다. 예를 들어 `172.16.10.20`은 전통적인 Class B 범위이면서 사설 주소이다. `172`로 시작하는 모든 주소가 사설 주소인 것은 아니다.

사설 주소는 서로 분리된 네트워크에서 중복 사용할 수 있다. 또한 사설 범위 밖의 주소라고 해서 전부 공인 IP인 것은 아니다. 루프백이나 링크 로컬 등 특별한 용도의 주소도 있다.

## IPv4 주소 부족과 대응 방법

인터넷에 연결되는 장비가 늘면서 전 세계적으로 사용할 수 있는 IPv4 주소가 부족해졌다. 대표적인 대응 방법은 다음과 같다.

- **IPv6 사용:** 128비트 주소 체계를 사용해 훨씬 많은 주소를 제공한다.
- **사설 IP 사용:** 내부 네트워크에서는 사설 주소를 사용해 각 장비를 구분한다.
- **NAT 사용:** 라우터 등이 내부 사설 IP와 외부 공인 IP 사이의 주소 변환을 수행한다. 가정이나 사무실에서는 여러 내부 장비가 하나의 공인 IPv4 주소를 공유하도록 하는 경우가 많다.

NAT는 IPv4 주소를 절약하는 데 도움이 되지만, IPv4 주소 공간 자체를 늘리는 것은 아니다.

## Subnet Mask

서브넷 마스크는 IPv4 주소의 **네트워크 부분과 호스트 부분을 구분하는 값**이다.

- Network: 어떤 네트워크에 속하는가?
- Host: 그 네트워크 안의 어떤 인터페이스인가?

```text
IP Address  : 192.168.10.100
Subnet Mask : 255.255.255.0

192.168.10 | 100
 Network  | Host
```

이 마스크에서는 앞의 24비트가 네트워크 부분이고, 뒤의 8비트가 호스트 부분이다.

### 같은 서브넷에 속하는 주소

다음 주소들은 모두 `/24`라고 가정한다.

```text
192.168.10.10/24
192.168.10.20/24
192.168.10.30/24
```

네트워크 주소는 `192.168.10.0/24`로 같고, 호스트 부분은 다르다.

반면 다음 두 주소는 `/24` 기준으로 서로 다른 서브넷에 속한다.

```text
192.168.10.10/24 → 192.168.10.0/24
192.168.20.10/24 → 192.168.20.0/24
```

서브넷 마스크가 달라지면 같은 주소끼리 비교하더라도 결과가 달라질 수 있다. 예를 들어 위 두 주소를 모두 `/16`으로 설정하면 같은 `192.168.0.0/16` 서브넷에 속한다.

## CIDR의 /24 의미

`/24`는 왼쪽부터 24비트를 네트워크 부분으로 사용한다는 뜻이다.

```text
11111111.11111111.11111111.00000000
   255  .   255  .   255  .    0
```

`192.168.10.0/24`는 다음과 같이 나뉜다.

| 항목 | 값 |
|------|----|
| 네트워크 주소 | `192.168.10.0` |
| 호스트 부분 | 마지막 8비트 |
| 일반적으로 호스트에 할당하는 범위 | `192.168.10.1` ~ `192.168.10.254` |
| 브로드캐스트 주소 | `192.168.10.255` |
| 전체 주소 수 | 256개 |
| 일반적인 호스트 할당 가능 수 | 254개 |

`192.168.10`은 네트워크 부분을 설명하기 위해 줄여 쓴 표현이고, 완전한 네트워크 주소는 `192.168.10.0`이다. 이때 호스트 비트가 모두 0이므로 네트워크 자체를 나타낸다.

주소와 마스크를 비트 AND 연산하면 네트워크 주소를 구할 수 있다.

```text
192.168.10.100 AND 255.255.255.0 = 192.168.10.0
```

앞의 세 옥텟과 마지막 한 옥텟으로 나누는 설명은 `/24` 예시에 해당한다. `/26`처럼 옥텟 중간에서 경계가 나뉘는 마스크도 있다.
