# LAN과 WAN의 데이터 전달 과정

IPv4와 Ethernet을 기준으로 데이터가 전달되는 흐름을 정리한다. 주소가 변환되는 NAT나 터널링은 제외한다.

## 먼저 확인할 것

송신 PC는 목적지 IP 주소와 자신의 IP 주소, 서브넷 마스크를 이용해 목적지가 같은 서브넷에 있는지 판단한다. 실제 전송 경로는 라우팅 테이블을 기준으로 선택한다.

```text
같은 서브넷으로 직접 전달 → 목적지 장비로 전송
다른 네트워크로 전달     → 경로에 지정된 게이트웨이로 전송
```

기본 게이트웨이는 더 구체적인 경로가 없을 때 사용하는 기본 경로의 다음 홉이다. 사용할 수 있는 경로가 없다면 데이터를 전달할 수 없다.

## LAN 내부에서 전달

```text
PC 1 ── Switch ── PC 2
```

1. 목적지 IP가 같은 서브넷에 있는지 확인한다.
2. 목적지 IP에 대응하는 MAC 주소가 ARP 캐시에 있는지 확인한다.
3. 정보가 없으면 ARP Request와 Reply로 MAC 주소를 알아낸다.
4. 목적지 IP를 담은 IP 패킷을 만든다.
5. PC 2의 MAC 주소를 목적지로 하는 Ethernet 프레임에 IP 패킷을 담는다.
6. 스위치가 목적지 MAC 주소를 기준으로 프레임을 전달한다.
7. PC 2가 프레임에서 패킷을 꺼내 상위 계층으로 전달한다.

일반적인 Layer 2 스위치는 IP 주소를 기준으로 경로를 선택하지 않는다. 목적지 MAC의 포트를 아직 모르면 같은 VLAN에서 수신 포트를 제외한 포트들로 전달할 수 있다.

## WAN을 거쳐 다른 네트워크로 전달

```text
PC ── Switch ── Gateway(Router) ── 여러 Router ── 목적지 LAN ── Server
```

출발지와 목적지 LAN은 Ethernet이며, 기본 게이트웨이를 사용하는 상황을 가정한다. 같은 절차는 WAN이 아닌 다른 서브넷 사이의 통신에도 적용된다.

1. 목적지 IP 주소를 확인한다.
2. 목적지가 다른 네트워크에 있음을 확인한다.
3. 라우팅 테이블에서 기본 게이트웨이를 다음 홉으로 선택한다.
4. 캐시에 정보가 없으면 ARP로 게이트웨이의 MAC 주소를 확인한다.
5. 목적지 IP는 서버 주소로, 목적지 MAC은 게이트웨이 주소로 지정해 프레임을 만든다.
6. 스위치를 거쳐 게이트웨이에 프레임을 전달한다.
7. 라우터가 수신 프레임에서 IP 패킷을 꺼내 목적지 IP 주소를 확인한다.
8. 라우팅 테이블을 이용해 출력 인터페이스와 다음 홉을 선택한다.
9. 출력 링크에 맞는 새 프레임으로 전달하며, 필요한 라우터마다 이 과정을 반복한다.
10. 목적지 네트워크에 연결된 라우터에 도착한다.
11. 마지막 구간이 Ethernet이면 필요한 경우 ARP로 서버의 MAC 주소를 확인한다.
12. 서버를 목적지 MAC으로 지정한 Ethernet 프레임을 전달한다.

중간 구간의 링크 방식은 Ethernet, PPP 등으로 다를 수 있다. 따라서 모든 WAN 구간에서 Ethernet 프레임이나 ARP를 사용하는 것은 아니다.

## IP 패킷과 Ethernet 프레임

프레임은 IP 주소와 MAC 주소를 같은 위치에 나란히 적는 구조가 아니다. IP 패킷을 Ethernet 프레임 안에 담는다.

```text
Ethernet Frame
├─ Ethernet Header: 출발지 MAC / 목적지 MAC 등
├─ IP Packet
│  ├─ IP Header: 출발지 IP / 목적지 IP 등
│  └─ TCP·UDP 헤더와 응용 데이터 등
└─ Ethernet Trailer: 오류 검출 정보(FCS)
```

## 라우터를 거치면서 바뀌는 것

| 항목 | 전달 과정 |
|------|-----------|
| 출발지·목적지 IP | NAT 등이 없다면 유지 |
| 출발지·목적지 MAC | 각 Ethernet 링크의 송신 인터페이스와 다음 수신 인터페이스 주소로 설정 |
| IPv4 TTL | 라우터를 거칠 때 감소 |
| 링크 계층 프레임 | 출력 링크에 맞게 새로 구성 |

홉(Hop)은 경로상의 한 전달 단계를 뜻하며, 라우팅에서는 거치는 라우터 수를 셀 때 사용한다.

목적지까지 가는 기준은 IP 주소이고, 현재 Ethernet 링크에서 다음 장비로 보내는 기준은 MAC 주소이다. 서버의 응답도 서버 쪽 라우팅 정보를 기준으로 전달되므로 요청과 같은 경로로 돌아온다고 단정할 수는 없다.
